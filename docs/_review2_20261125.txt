README 仍写“现有机场布局下，起降点不宜设在净空保护区内”。建议改成：“在本研究采用的机场走廊硬约束与当前端点设置下，4 组机场向 OD 不可达；这不是对真实空域边界或起降政策的判断。”报告摘要、讨论与结论已有类似限定，建议全包一致。

2. 把 λ 切换值写成采样结果
正文表格已给出 0.025–0.80 与 0.825–2.0 两段采样区间，但摘要仍将 0.025 和 0.825简称为“切换点”。建议写清：等长解在 λ=0.025 的首个正采样点发生 tie-break 变化；绕行解在扫描中首次出现于 λ=0.825，对应转换区间 [0.800, 0.825]。根据表中路线目标值，等长低暴露解与绕行解的线性代价交点约为 λ=0.8075。若给出该解析值，应附计算式和输入数值；否则只报告采样区间。
3. 闭合数据与代码来源链
日志记录管线成功、13 步及 117.94 秒，但没有记录最终选用的人口栅格路径、数据版本或文件 SHA256。建议在日志中写入输入文件名、来源版本、大小、校验值及代码 commit。
SHA256 清单中的 PDF、图片和 CSV 共 21 项均校验通过；源码 zip、requirements、运行日志、README 和统计声明尚未列入。请扩大清单并注明覆盖范围。
源码 zip 标注 commit 7ab525d，但不含 .git 元数据，包内无法核对该压缩包与 commit/tag 的对应关系。建议保留完整 commit hash、git archive 命令或仓库 tag 页面。
69 项测试目前出现在说明文字中；提供的管线日志没有 pytest 运行记录。附上 pytest 输出或 CI 链接后，再称本次复现验证 69 项通过。

五、招生视角与下一步
本项目当前最能支撑申请的内容，是把低空航路问题转成可运行的空间优化原型，用公开人口数据做相对暴露比较，并能解释结果边界。它还不是运行决策用的安全航路系统，也尚未证明强于现有文献的研究新颖性。
作品集终稿建议控制在 4–6 页，展示问题、数据与模型、核心权衡图、一次敏感性发现、局限和下一步，以及可验证的个人贡献。用 commit、代码模块或结果版本说明你亲自完成了什么；避免将“暴露代理下降”表述成“安全提高”。
完成机场措辞、λ 采样标签、版本映射和来源链后，再进入申请版终稿审阅。
